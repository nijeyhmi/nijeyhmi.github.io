Function Component를 쓰는 경우 child component를 React.forwardRef로 감싸고, 부모 컴포넌트에서 자식 컴포넌트에 passHref 옵션을 추가한다

전달 받은 ref attribute를 하부 트리 내의 다른 컴포넌트로 전달하는 React 컴포넌트를 생성

→ 완전 번거로움….왜?

atomic 컴포넌트를 사용하는 다른 컴포넌트들은 일반적으로 내부 atomic 컴포넌트의 DOM 요소에 대한 ref 정보를 얻을 필요가 없다.

컴포넌트들이 서로의 DOM 구조에 지나치게 의존하지 않기 때문.

이런 캡슐화는 애플리케이션 레벨의 컴포넌트에서는 바람직하지만 재사용성이 높은 ‘말단’ 요소에서는 불편할 수 있다(e.g. 버튼 컴포넌트를 커스텀한 이전, 다음 버튼 컴포넌트 등)

이런 atomic 컴포넌트들은 일반적인 DOM button, input과 유사한 방법으로 애플리케이션 전체에 걸쳐 사용되는 경향이 있고, 이들의 이벤트 핸들링을 위해서는 DOM 노드 접근이 불가피할 수 있다.

→ 이때 forwardRef를 사용하는 것

상위 컴포넌트는 forwardRef를 통해 전달된 ref를 얻고, 그것을 렌더링되는 DOM button으로 전달한다

  1. React.createRef를 호출해서 React ref를 생성하고 ref 변수에 할당합니다.
  2. ref를 JSX 속성으로 지정해서 <FancyButton ref={ref}>로 전달합니다.
  3. React는 이 ref를 forwardRef 내부의 (props, ref) => ... 함수의 두 번째 인자로 전달합니다.
  4. 이 ref를 JSX 속성으로 지정해서 <button ref={ref}>으로 전달합니다.
  5. ref가 첨부되면 ref.current는 <button> DOM 노드를 가리키게 됩니다.

→ 이해는 되었는데… 그냥 svg 아이콘을 묶어놓은 컴포넌트에조차 ref를 받을 필요가 있나?

./node_modules/next/dist/client/link.js 에 들어가보니, childProps에 ref를 setRef하는 코드가 있었다.

이것 때문에 ref 관련 오류가 발생하는 듯…
