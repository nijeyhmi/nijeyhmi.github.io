채널톡 ALF, RAG를 선도할 수 있는 이유

ALF: 상담사를 대신해 고객의 문의 내용에 답변하는 AI 에이전트

  • 등록된 FAQ 기반으로 고객 문의 해결
  • 도큐먼트에서 공개된 아티클을 참고해 답변 생성
  • 고객 문의에 적합한 커맨드를 알아서 추천

ALF 구조: Routing + RAG

좋은 사용자 경험을 위해서는 못하면 못한다고 이야기하는 것이 필요함

전처리

  • 고객이 제공해준 정보를 LLM이 잘 활용할 수 있도록 가공(chunking)
  • 벡터로 만드는 과정(Embedding)

답변 생성

  • 질문과 관련이 있는 청크를 vector DB에서 검색

chunking: LLM 응답의 품질에 직접적인 영향을 끼치는, 문서나 데이터를 작은 조각으로 나누는 과정

  • 의미적 단위로 묶어야 함
  • overlap을 적절히 주어야 함
  • embedding 모델의 특징을 반영해야 함
  • 평가를 적절히 진행해야 함

Fact check가 중요 → 할루시네이션을 방지해야 함. 답변을 할 수 있는지 없는지를 fact check로 처리함

Fact check: 이 답변이 사용자의 질문에 사실에 기반한 적절한 답변인가?

  • Answer relevancy: 질문의 내용을 답변으로 해결해 주었는가?
  • Context relevancy: 주어진 청크가 질문 해결에 도움이 되는가?
  • Faithfulness: 답변이 주어진 청크를 기반으로 생성되었는가?
  1. 답변은 반드시 청크를 기반으로 생성되어야만 한다
  2. Context relevancy, faithfulness를 만족하면 LLM은 적절한 답변을 생성한다

UI를 꼭 사람이 짜야 할까요?

UI 작업은 프론트엔드 개발의 “병목”이다.

Bezier 디자인 시스템을 사용중

Figma에서 코드로, 그런데 디자인 시스템을 접목시켜 구현해야 함

알고리즘으로 푸는 경우 변환 로직 의존도가 높아짐. 유지보수가 불가능

→ LLM으로 회색 지대를 해결해보자고 생각

  1. Figma Image → Code

    충분한 성능을 내지 못함

    • 정보의 유실
    • 정확도 부족

  2. Figma XML → Code

    피그마 노드 데이터를 LLM이 적절하게 활용할 수 있도록 피그마 플러그인을 개발

    코드 생성을 위한 최적의 형태로 LLM 전달이 가능해짐

    변환 로직이 피그마쪽 스택에만 의존하므로 의존도도 낮아짐

Cursor를 활용

반복 작업을 줄이고 개발 생산성을 높이는데 도움을 줌

매번 고품질의 결과를 얻기 위해서는 적절한 컨텍스트 전달이 필요 → 이를 위해 Cursor Rules 사용

Cursor Rules: LLM이 동적으로 참조할 수 있는 프롬프트

  1. 기본 뼈대 만들기(디자인 ⇒ 코드 초안)
  2. 의미 있는 덩어리로 묶기(컴포넌트 군집화)
  3. 똑똑하게 다듬기(디자인 시스템 명세 기반 코드 완성)
  4. 최종 점검 및 마무리(품질 향상)

Cursor Rules 구현

  1. Single Turn 방식: 한 턴에 모든 작업 수행

    모든 로직과 컨텍스트를 단일 룰에 적용

    → 할루시네이션 발생. 너무 긴 컨텍스트를 제공했기 때문

  2. Multi Turn 방식: 파이프라인을 노드 단위로 쪼개기

    여전히 컨택스트가 넘치는 것은 막을 수 없음

    초과하지 않더라도 컨택스트가 길어지면 할루시네이션을 피하기 어려움

  3. Multi Turn + Multi Chat: 넘치려고 하면 쪼개서 독립적으로 실행

    각 노드간 공유되어야 하는 관심사는 메모리에 저장

버그 대응과 PR 리뷰 시간 90% 단축시킨 방법

Cursor와 MCP(Model Context Protocol)가 만나면?

1. 버그 대응

실제 시스템상 버그인지, 고객사의 세팅문제인지 모르기 때문에 리소스를 많이 써야함

소모적인 버그 분석, 혁신이 필요했음

2. PR 리뷰

밀려드는 PR로 인해 리뷰가 병목 지점이 되어 버림

⇒ 개발 속도와 코드 퀄리티를 모두 잡아보자

MCP와 프롬프트

기준과 절차를 따라 결과를 요청

AI를 위한 초정밀 업무 메뉴얼로 발전시킴

프롬프트 작성 시에는 할루시네이션 없이 명확히 실행이 가능하도록 함
